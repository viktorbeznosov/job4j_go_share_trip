# ShareTrip — проектные инструкции

## Проверки перед завершением задачи

В проекте уже настроены команды `make lint` и `make test`.

При выполнении **любой задачи** в этом репозитории необходимо учитывать эти проверки:

1. После внесения изменений запускать `make lint` и исправлять все ошибки линтера.
2. Запускать `make test` и исправлять все упавшие тесты.
3. Не считать задачу завершённой, пока обе проверки не проходят успешно.
4. Не отключать и не ослаблять существующие проверки линтера или тестов только для того, чтобы получить успешный результат.
5. Если изменение затрагивает существующие тесты или добавляет новую функциональность, при необходимости дополнять/обновлять тесты, сохраняя текущие требования проекта.

### Команды

```bash
make lint
make test
```

`make lint` запускает `golangci-lint` для всего проекта, а `make test` запускает тесты из `./internal/...`.

## Общие правила работы

- Сначала изучать существующую структуру проекта и доменную модель, прежде чем менять код.
- Сохранять существующие архитектурные и доменные соглашения проекта.
- Делать минимальные изменения, необходимые для поставленной задачи.
- После изменений обязательно проверять результат через `make lint` и `make test`.
