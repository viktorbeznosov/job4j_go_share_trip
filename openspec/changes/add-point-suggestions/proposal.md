# Proposal

## Why

Поля «Откуда»/«Куда» в формах создания поездки и заявки (`route-form.component.ts`) и фильтры списка поездок на фронте заполняются вручную свободным текстом. Из-за этого один и тот же город пишется по-разному (`Москва`, `москва`, `Москва `), фильтр по точному совпадению (`t.from_point = ?`) ничего не находит при опечатке или частичном вводе, и пользователь не знает, какие пункты вообще существуют в системе.

Нужен подсказчик пунктов: пользователь вводит подстроку (`мос`, `И`) и получает до 10 существующих пунктов для выбора.

## What Changes

- Новый HTTP-endpoint, отдающий список уникальных пунктов (`from_point` и `to_point`) из таблиц `trips` и `trip_requests`.
- Подстрочный поиск без учёта регистра: `term=мос` находит `Москва`, `term=И` находит `Иркутск` и `Ижевск`.
- Ответ ограничен первыми 10 совпадениями.
- Endpoint доступен всем аутентифицированным ролям (driver, passenger, director, admin) — **без** фильтрации по статусам и по правам видимости: подсказчик отдаёт весь словарь пунктов системы.
- Поиск по подстроке — новое поведение: существующие фильтры списков работают только по точному совпадению и остаются без изменений.

## Capabilities

### New Capabilities

- `point-suggestions`: подсказка пунктов маршрута — выдача уникальных `from`/`to`-пунктов существующих поездок и заявок с подстрочным поиском без учёта регистра и ограничением на 10 результатов, доступная всем аутентифицированным ролям.

### Modified Capabilities

(нет — это первая спецификация в проекте, существующие capabilities не меняются)

## Impact

- **Код:**
  - `internal/api/route.go` — новый маршрут в группе с существующими;
  - новый обработчик в `internal/api/` + ответ-обёртка в `internal/api/response.go` (по действующему AGENTS.md);
  - `internal/api/errors/` — возможно, новая ошибка валидации `term`;
  - `internal/business/trip/repository/` или новая небольшая точка доступа — SQL-запрос с `ILIKE` к `trips` и `trip_requests` (две таблицы UNION);
- **API:** новый контракт для фронта `job4j_go_share_trip_front` (отдельный репозиторий, вне границ этого изменения — потребует своего change там);
- **БД:** без миграций — `from_point`/`to_point` уже `TEXT NOT NULL` в обеих таблицах;
- **Производительность:** `ILIKE '%term%'` не использует обычный B-tree-индекс; на объёмах учебного проекта это допустимо, индекс (`pg_trgm`) вне scope и отмечено в design;
- **Тесты:** новые интеграционные тесты в `internal/api/api_test/` (Docker обязателен), проверка по-русски через типизированные обёртки ответов.
